# Узгодження ПР-1–ПР-7 (фінальна редакція ПР-8)
Вихідні матеріали збережено без змін у `materials/`; ця редакція має пріоритет над суперечностями в них.

| Сценарій | Компоненти (ПР-4) | Точки рішень | Статус |
|---|---|---|---|
| UC-01 Фази в годину пік | 2→3→4→5, 7 | DP-01, 02, 09 | Проєкт |
| UC-02 Зелений коридор | 1→4→3; 2→3→4→5; 7 | DP-03, 04, 10, 09 | ETA і симуляційні правила реалізовано, решта проєкт |
| UC-03 ДТП | 2→3→4→1/6; 7 | DP-05, 06 | Проєкт |

| UC-05 Пріоритет автобуса | 2→3→4→5; 7 | DP-08 | Проєкт |
| UC-06 Звіт | 1→4→3↔7→4→1 | Запит звіту, недостатність даних | Проєкт |

## Уточнення
- ПР-1: 15–20% економії часу — очікуваний ефект, не результат експерименту. Автоматичний пріоритет не виключає людського контролю.
- ПР-2: camera_id/vehicle_class забезпечують майбутній CV; timestamp/GPS → відстань, швидкість і вік GPS; IoT → черга (разом із CV), щільність і швидкість потоку; weather_cond → код погоди; timestamp → година/день. Історія — джерело навчання у майбутньому, не окрема ознака поточного прототипу. Синтетичний CSV не містить сирих GPS/відео.
- DP-01: >70% запускає аналіз, >75% — запропонована зміна фази; DP-02: схожість >85% — дедуплікація CV у №3 з підготовкою №2; DP-09: >5 аномалій/хв — заплановане правило №2; критичні відсутні дані ETA не заповнюються довільно.
- DP-03: 2–3 варіанти, різниця >2 хв — рекомендація швидшого, але підтвердження водієм завжди обов'язкове.
- DP-04: у діаграмі послідовності ПР-3 стрілку ШІ→контролер замінено на ШІ→№4→№5; 15 с — поріг рекомендації, не гарантія достатнього часу для безпечної зміни фаз. DP-10: GPS >5 с → скасування автоматичного режиму, диспетчер, штатний цикл.
- DP-05/06: ПР-3 містить >0.90 для автопідтвердження і >0.98 для автосповіщення. Фінальне консервативне правило: >0.90 — кандидат для перевірки; публікація лише після підтвердження людиною або майбутньої валідованої політики >0.98. У навчальній версії CV відсутній, публікація не виконується. DP-07 — локальні дані мають пріоритет при конфлікті, людина може скасувати; DP-08 — автобус >3 хв і поперечна черга <15, швидка має вищий пріоритет.
- ПР-5/6: 10–90% — номінально 80% інтервал; confidence_score — евристика, не ймовірність. Випадковий поділ для синтетики, часовий поділ для реальних даних. Код ПР-8 перевіряє інтервал, діапазони та ескалацію згідно з ПР-7, не перенавчаючи модель.
- NFR з ПР-3 (500 мс, 99.99%, 5 с, privacy, пояснюваність, аудит) — вимоги дизайну, не сертифіковані результати. Необхідне окреме тестування повної системи.
