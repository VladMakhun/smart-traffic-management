## Уточнення
- ПР-1: 15–20% економії часу — очікуваний ефект, не результат експерименту. Автоматичний пріоритет не виключає людського контролю.
- ПР-2: camera_id/vehicle_class забезпечують майбутній CV; timestamp/GPS → відстань, швидкість і вік GPS; IoT → черга (разом із CV), щільність і швидкість потоку; weather_cond → код погоди; timestamp → година/день. Історія — джерело навчання у майбутньому, не окрема ознака поточного прототипу. Синтетичний CSV не містить сирих GPS/відео.
- DP-01: >70% запускає аналіз, >75% — запропонована зміна фази; DP-02: схожість >85% — дедуплікація CV у №3 з підготовкою №2; DP-09: >5 аномалій/хв — заплановане правило №2; критичні відсутні дані ETA не заповнюються довільно.
- DP-03: 2–3 варіанти, різниця >2 хв — рекомендація швидшого, але підтвердження водієм завжди обов'язкове.
- DP-04: у діаграмі послідовності ПР-3 стрілку ШІ→контролер замінено на ШІ→№4→№5; 15 с — поріг рекомендації, не гарантія достатнього часу для безпечної зміни фаз. DP-10: GPS >5 с або невалідний → відхилення прогнозу, блокування нових запитів, безпечне завершення активних фаз контролером, підтвердження ACK, диспетчер; штатний цикл лише після безпечного переходу. Без ACK стан невідомий, локальний захист та ескалація. DP-04: незалежна перевірка конфліктів фаз, пішоходів і захисних інтервалів; у прототипі не реалізовано фізичний контролер.
- DP-05/06: ПР-3 містить >0.90 для автопідтвердження і >0.98 для автосповіщення. Фінальне консервативне правило: 0.90 < c ≤ 0.98 — кандидат на ручне підтвердження; c ≤ 0.90 — додаткова перевірка або відхилення; c > 0.98 — потенційна автоматизація лише після валідації. У поточній версії усі підтвердження ручні; публікація тільки підтвердженої події. У навчальній версії CV відсутній, публікація не виконується. DP-07 — локальні дані мають пріоритет при конфлікті, людина може скасувати; DP-08 — автобус >3 хв і поперечна черга <15, швидка має вищий пріоритет.
- ПР-5/6: 10–90% — номінально 80% інтервал; confidence_score — евристика, не ймовірність. Випадковий поділ для синтетики, часовий поділ для реальних даних. Код ПР-8 перевіряє інтервал, діапазони та ескалацію згідно з ПР-7, не перенавчаючи модель.
- NFR з ПР-3 (500 мс, 99.99%, 5 с, privacy, пояснюваність, аудит) — вимоги дизайну, не сертифіковані результати. Необхідне окреме тестування повної системи.

- Оновлена ПР-3 містить матрицю відповідальності всіх DP-01–DP-10, деталізовані процедури DP-04/05/10 та оновлену діаграму UC-02. Це уточнення проєктних вимог, не нові результати експериментів.
